Method and definitions

Terms. A configuration is a model at one reasoning level. What the numbers mean. Score depends on the Y axis. Opifex Score (default) is our weighted combination of the configured coding benchmarks and the knowledge benchmark, using local weights. It is our calculation, not an index published by Artificial Analysis. The knowledge score is an index, not a pass rate: correct answers add, hallucinated answers subtract, and abstentions are neutral, so it can be negative, as can the Opifex Score. Cost and tokens for this score use the configured coding benchmarks; the knowledge benchmark is a quality signal, not a workload. The Coding bucket is our weighted combination of those coding benchmark scores using the current methodology weights. The component scores and Coding bucket weights come from the source data. Cost and tokens follow the Y axis by default. Each evaluation's per-task cost and output tokens use its current methodology task count. "Full Intelligence Index" uses the evaluations and weights in the current methodology. The index cost is always shown as a reference column. Cost per task is recomputed from per-evaluation token counts: cacheable input × measured cache-hit rate at the cache-read price, remaining input at the cache-write price (or input price when unavailable), and reasoning plus answer tokens at the output price, divided by that evaluation's task count. Output tokens / task are computed the same way using reasoning plus answer tokens. Score per $ and per 100k tokens use the current Y axis and only make sense among models that pass your min score. Elbow by model = within each selected model, configurations sorted by the current X axis; configurations worse and pricier than a cheaper configuration of the same model are greyed out; slope = extra points ÷ log10(x ratio) between consecutive non-dominated configurations (points per 10× more cost or tokens); the elbow is the level just before the largest drop in slope, provided no later step is steeper than the step into it; otherwise there is no real elbow and the top level is marked (needs at least 3 non-dominated configurations). Each slope drop carries a standard error propagated from the scores' standard errors. An elbow is proven when its drop exceeds the noise threshold times that error and no other candidate is statistically tied; otherwise the tool shows the elbow region and does not pick. A step between two configurations is a proven gain when the score difference exceeds the noise threshold times the standard error of the difference (solid effort-line segment, green "Gain · σ · cost×"); otherwise it is not proven (dashed, grey). Proven gains: from a model's cheapest frontier configuration, each arrow jumps to the cheapest configuration that is a proven gain over the previous one. Marginal $ / extra pt = for each configuration on the cost Pareto line, (its cost − the previous Pareto configuration's cost) ÷ (its score − that configuration's score): what each extra point on the current Y axis costs when you step up; hover the value to see the step. Monthly cost = cost per task × tasks per day × days per month, at API list prices: an API-equivalent value for comparing models, not what a flat subscription charges; the default 10 tasks/day × 30 days is a round placeholder, not a usage estimate, so set your own volume. Min score is a view filter with no default (0): it is a preference, so the tool shows every configuration until you set one; in relative mode it is a percentage of the current top score among selected models. Noise. Each score's standard error uses the task counts and weights in its scoring metadata. Pass-rate benchmarks use √(p(1−p)/N); the knowledge index, based on +1/−1/0 per question, is bounded by √((1−I²)/N). Composite scores combine component errors using the current weights. These are conservative (unpaired) bounds. "Dominated" = another selected configuration is at most the same on the current X axis and better by more than the noise threshold (1σ or 2σ of the difference). The noise threshold is the only convention in these rules. The default is 2σ, the conventional level for calling a difference proven (about 95%); 1σ is available for an exploratory reading. Quadrant = AA's: the top-left quarter of the plot area, purely geometric. Configurations without a published price, or with a $0 price, are not shown (they cannot be placed on a cost axis). Selection is saved in the URL hash; AA's ?models= slugs also work.
